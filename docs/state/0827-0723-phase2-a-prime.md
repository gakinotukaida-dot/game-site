## 3. 変更点A：`view02_rank_v2.py`
### 3-1. `BASELINE_MODE=hour_matched` のときだけ、次を行う
1. **分母の差し替え**＝`Q_BASELINE_DIAG` の narrow（`align_secs = RECENT_HOURS*3600`）**1系統のみ**を実行し、`n_days >= MIN_BASE_DAYS` の行は `baseline` / `q1` / `q3` を A′ 値へ差し替える。差し替えるのは**分母系の3値のみ**＝分子（`recent_value`）・`shrunk` の `n_points`・`boost` は現行のまま（`_diag_score` と同じ線・`0802D-27`）。**順位（eff）も表示（ratio）も同じ差し替え後の値から計算する**（順位と表示で分母が割れると自己矛盾チップが再発する）。
2. **フォールバックの印**＝`n_days < MIN_BASE_DAYS` の行は現行 `base` CTE の値のまま採用し、行に印を立てる（JSON へ `"al": 0`。A′採用行は `"al": 1`）。**確度を一段下げる**＝`high→mid`・`mid→low`・`low→low`（`conf_code` を印の直後で降格。`0802E-05` の線）。
3. **今日の窓に観測ゼロの行は倍率を出さない**＝`Q_RECENT_OBS_DIAG` を引き、`recent_obs` に無い appid は `detection.ratio` を `None`、`recent_value` も `None` にする（`COALESCE(recent_q, current_ccu)` で数日前の1点に落とす経路を塞ぐ・`0808-2310-03`）。順位付けは `raw_ratio=None`→`base_score` が 0 を返す既存経路に乗せ、新しい分岐を作らない。表示は既存の「分子なし文」（`0808-2225-15-03` の型）に落ちる。
4. **JSON への追記（hour_matched のときのみ）**＝各行に `"al"`（上記）、トップレベルに `"up_thresh": RISING_UP_THRESH` と `"baseline_mode": "hour_matched"`。
### 3-2. `BASELINE_MODE=all`（既定）のとき
- **新規クエリを1本も実行せず、JSON に新キーを1つも足さない。** 出力・ログとも現行と完全一致（「1ビットも変わらず」の実装定義）。既存の `BASELINE_DIAG`（フェーズ1）経路とは独立に共存させる。

## 4. 変更点B：`index.html`
1. **しきい値の外部化**＝`usualChip()`・`heroPick()`・`paintHero()` の `1.3` を `(P.up_thresh || 1.3)`（view02 データに同梱の値・無ければ 1.3）へ。**view02 以外のビューは従来どおり 1.3 のまま**＝分母定義が現行のままのビューに 1.6 を適用しない（各ビューのしきい値は各データ源に従う。意味上は全タブ「平常の約1.3倍相当」で揃う）。
2. **印の表示**＝`al===0` の行に「時間帯をそろえられませんでした」チップ（控えめ・強調なし）を出す。確度表示は JSON の `confidence` をそのまま使う（降格は Python 側で済んでいる＝二重に下げない）。
3. **中継点を落とさない**＝`viewItems(view==="2")` が行を**明示的なキー列挙で組み直す**ため、`al` を列挙に足さないと描画まで届かない（`0808-2225-17` の再発防止・下記ホップ⑦）。`loadRising()` 側の受け取りも同様。
4. JSON に新キーが無い（＝all のまま）場合は従来表示に自然に落ちること（後方互換）。
